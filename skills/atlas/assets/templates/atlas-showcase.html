Atoms and components, accessible by construction

Every colour pairing below is proven by check_contrast.mjs, every control shows the same two-tone focus ring, every state is carried by more than colour, and every widget follows the WAI-ARIA Authoring Practices keyboard map. Toggle the theme in the header; everything holds in dark mode and under reduced motion, high contrast and forced colours.

Colour

Each step is solved for a fixed contrast against white (1.06 → 17.5), so step 600 on white is always 5.4:1 and step 300 on 900 is always 7.5:1, in every hue.

Typography

Rem-based so browser zoom and font-size settings scale everything (1.4.4). Body line-height is 1.5 and survives the 1.4.12 text-spacing overrides. Nothing is set below 12px.

Focus and targets

One ring everywhere: 2px brand outline, 2px offset filled with the surface colour. The inner halo keeps the ring at ≥ 3:1 on any background (2.4.7, 2.4.11). Press Tab to see it.

Targets. Every control is at least 24×24 CSS px (2.5.8); buttons, list rows, choices and nav items are 40–56px tall, and touch-primary actions use .at-btn--lg (48). Spacing between adjacent targets is never below 8px.

Buttons and links

One primary per view. Icon-only buttons carry aria-label. Loading keeps the label in the DOM and sets aria-busy. Disabled buttons stay in the tab order when the reason is explained nearby; otherwise use disabled.

Links inside text are underlined, so colour is never the only cue. Standalone link →

Inputs, textarea, select

Borders are 3:1 against the surface (1.4.11). Placeholder is real text at 4.5:1 but never the only label. Invalid fields get a 2px danger border plus an icon and message.

Checkbox, radio, switch, segmented

Real native inputs drawn with appearance: none, so they keep their semantics and keyboard behaviour. The whole label is the hit area (44px). A switch is a button[role=switch] for an immediate effect; use a checkbox when the change is submitted later.

Spinner, progress, skeleton, tooltip

Form and field

Label above, hint below, error replaces the hint and is linked with aria-describedby. On submit, focus moves to an error summary that links to each field (3.3.1, 3.3.3). Autocomplete tokens are set (1.3.5). Nothing re-asks for data already entered (3.3.7).

Alerts, banners, toasts

Inline alerts persist and sit where the problem is. Toasts live in one polite live region, pause on hover and focus, and errors never auto-dismiss (2.2.1, 4.1.3).

Dialog, drawer, menu, popover

Dialogs use the native element with showModal(): focus is trapped, the background is inert, Escape closes, and focus returns to the opener. Menus follow the APG menu-button pattern. Popovers are non-modal and close on Escape, outside click or focus leaving.
